Build a polished, production-style web UI for a multi-tenant Call Center Management application called “Nubitel Call Center”.

IMPORTANT:
- Create only the frontend application.
- Do not replace or rewrite the existing Go backend.
- The frontend must run locally and connect to an existing REST API.
- Use the existing Swagger specification as the API contract when available:
  - /docs/swagger.yaml
  - Runtime Swagger UI: http://localhost:8080/swagger/index.html
- Active API base path:
  http://localhost:8080/call-center/api/v1
- Make the backend URL configurable using:
  VITE_API_BASE_URL=http://localhost:8080
- Do not hardcode sample data into UI components.
- Include an optional mock-data mode for frontend development when the Go API is unavailable:
  VITE_USE_MOCK_API=true

TECH STACK:
- React
- TypeScript
- Vite
- Tailwind CSS
- shadcn/ui
- React Router
- TanStack Query for server state and API calls
- React Hook Form with Zod validation
- Recharts for dashboard charts
- Lucide icons
- Axios or a clean fetch-based API client
- Vitest and React Testing Library for core tests

The application must work with:
npm install
npm run dev

GENERAL UI DIRECTION:
Create a clean, modern call-center operations dashboard. It should look professional and information-dense without feeling crowded.

Visual style:
- Dark navy sidebar
- Light neutral main background
- White cards with subtle borders and shadows
- Blue as the primary action color
- Green for Available/Ready/Idle
- Amber for Ringing/Offering/Waiting
- Red for Busy/errors/destructive actions
- Gray for Logged Out/Not Ready
- Responsive desktop-first layout
- Accessible color contrast
- Keyboard-accessible forms and dialogs
- Light and dark themes
- Loading skeletons, empty states, errors, confirmation dialogs, and toast notifications

Use a persistent left sidebar containing:

The top bar should contain:

Because the currently active backend may not expose a domain-list endpoint, create a domain selector that:

- Sends it as domain_name when required by the API

PAGES AND FEATURES:

1. OVERVIEW DASHBOARD

Show KPI cards:
- Total agents
- Available agents
- Busy agents
- Logged-out agents
- Active campaigns
- Waiting callers
- Calls being tried
- Calls being received
- Answered calls

- Recent operational events panel

Queue member statistics include:
- Waiting

- Receiving
- Answered
- In a queue call

2. LIVE OPERATIONS

Create a real-time operations board with:
- Campaign cards
- Waiting/trying/receiving/answered counts
- Agents grouped by Available, Ringing, Busy, Idle, and Logged Out
- Search and status filters
- Manual refresh and auto-refresh
- A detail drawer for an agent
- A detail drawer for a campaign

Clearly distinguish these independent states:
- Global agent status: Available, Ready, Busy, Logged Out
- Campaign/tier status: Ready, Available, Not Ready, Offering, Busy
- Call status: Idle, Ringing, Busy

Do not merge these into one ambiguous status.

API CLIENT REQUIREMENTS:
- Create a central typed API client.
- Organize endpoints into modules:
  - agentsApi
  - queuesApi
  - tiersApi
  - statsApi
  - cdrApi
  - syncApi
- Properly encode all query parameters.
- Normalize backend errors into:
  {
    status: number,
    message: string,
    fieldErrors?: Record<string, string>
  }
- Handle:
  - 400 as invalid request
  - 404 as domain/queue/agent/tier not found
  - 409 as duplicate or reservation conflict
  - 413 as request too large
  - 500 as server error
  - network failures as backend unavailable
- Do not silently hide errors.
- Add request cancellation where appropriate.
- Use TanStack Query cache invalidation after mutations.
- Poll only on live/dashboard pages and stop polling when the page is hidden.
